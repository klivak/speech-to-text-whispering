# Архітектура whisper-uk

Застосунок — один процес з одним UI-потоком і кількома допоміжними потоками.
Жодного вебвʼю чи вікон: уся взаємодія через іконку в треї.

## Потік даних

```
            ┌─────────────────────────────────────────────┐
            │            головний UI-потік (tao)            │
   хоткей → │  State: Idle → Recording → Transcribing → …   │
            └───────┬───────────────────────────┬──────────┘
                    │ start/stop                 │ результат
                    ▼                            ▲
            ┌───────────────┐          ┌──────────────────────┐
            │  audio (cpal) │  WAV →   │ worker-потік:         │
            │  запис у буфер│          │ groq.rs → paste.rs    │
            └───────────────┘          └──────────────────────┘
```

## Модулі (`src/`)

| Файл | Відповідальність |
|------|------------------|
| `main.rs` | Цикл подій `tao`, іконка/меню трея, кінцевий автомат станів, маршрутизація подій. |
| `config.rs` | Структура `Config`, читання/запис `%APPDATA%\whisper-uk\config.json`. |
| `hotkey.rs` | Парсинг рядка `"Ctrl+Alt+Space"` → `global_hotkey::HotKey`. |
| `audio.rs` | Запис мікрофона через `cpal` у моно-буфер `f32`, кодування у WAV (16-bit PCM) через `hound`. |
| `groq.rs` | `multipart`-запит до Groq (`/openai/v1/audio/transcriptions`), повертає текст. |
| `paste.rs` | Копіювання в буфер (`arboard`) та емуляція `Ctrl+V` (`enigo`). |
| `autostart.rs` | Автозапуск через реєстр `HKCU\...\Run` (тільки Windows, через `reg.exe`). |
| `stats.rs` | Лічильники використання Groq (`stats.json`): запити, слова, аудіо, денний лічильник по UTC-добі. |

## Потоки та події

`tray-icon` і `global-hotkey` віддають події через власні канали. Щоб не опитувати їх
у циклі (це палило б CPU), при старті піднімаються **два фонові потоки**, які блокуються
на `recv()` і пересилають події в головний цикл через `EventLoopProxy` як `UserEvent`.
Цикл працює в режимі `ControlFlow::Wait` — нуль навантаження в спокої.

**Транскрипція** виконується в окремому одноразовому потоці (HTTP-запит блокуючий, не
можна тримати UI). Результат повертається назад у цикл як `UserEvent::TranscribeDone`,
де оновлюється стан/іконка.

`cpal::Stream` не є `Send`, тож обʼєкт `Recording` живе **лише** в головному потоці.
У worker віддаються тільки готові WAV-байти (`Vec<u8>`).

## Кінцевий автомат

```
Idle ──(хоткей старт)──▶ Recording ──(хоткей стоп)──▶ Transcribing
  ▲                                                        │
  └──────────────(успіх / порожньо)◀───────────────────────┘
                          │ помилка
                          ▼
                        Error ──(наступний цикл)──▶ Idle
```

У режимі `toggle` старт і стоп — це натискання хоткея (`Pressed`). У `push_to_talk`
старт — `Pressed`, стоп — `Released`.

## Чому такі залежності

- **`tao`** — той самий цикл подій, що й у Tauri, але без вебвʼю; добре дружить з трей-крейтами.
- **`cpal`** — кросплатформне захоплення аудіо без важких залежностей.
- **`reqwest` з `rustls`** (без `native-tls`) — щоб не тягнути OpenSSL і лишити збірку легкою.
- Профіль `release` зібрано з `opt-level="z"`, `lto`, `strip` — звідси `.exe` ~2 МБ.
